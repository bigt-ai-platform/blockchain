# Layer0 Attack Vectors & Mitigations

> Status refresh: 2026-08-27 (production-hardening pass). Items marked
> `[FIXED]` are closed in the current tree; `[PARTIALLY FIXED]` have guards
> that still rely on operator discipline; the rest remain open. Consensus
> hardening status lives in `plan/pos-production-readiness.md`.

## Network Layer

### 1. Eavesdropping / Man-in-the-Middle — STILL OPEN

Plain HTTP is the default — SSL is disabled (`SSL=false`). Gossip, API keys,
transactions, and auth tokens travel in cleartext.

**Mitigation:**
- Set `SSL=true` and mount a deployment-specific PKCS12 keystore generated by
  `helper/prod/generate_keystore.sh` (the development keystore formerly
  committed to the repo was removed from tracking and must never be used).
- Terminate TLS at a reverse proxy (nginx, Cloudflare Tunnel) in front of
  `layer0-server`.
- On Mainnet the server logs a startup `SECURITY:` warning while TLS is off.

### 2. No Endpoint Authentication — PARTIALLY FIXED

`permissioned=false` by default — most REST endpoints accept requests from
anyone with network access. **Fixed for the sensitive PoS endpoints:**
`stakeDeposit`, `activateValidator`, `processWithdrawal`, `setValidatorKey`
require the `X-Api-Key` header when `server.apiKey` is set (constant-time
compare); Mainnet logs a warning when the key is unset. Read endpoints and
transaction submission remain open.

**Mitigation:**
- Always set `server.apiKey` (`SERVER_APIKEY`) in production.
- Set `permissioned=true` where all 55 endpoints must require an
  `accessToken` header (`pubkey,signature,sessionRandom`).
- Use a firewall/VPC to restrict access to trusted IPs.

### 3. Private Key Exfiltration via setValidatorKey — PARTIALLY FIXED

The handler no longer accepts a hex private key in the request body (the old
path accepted one over HTTP), and the endpoint is API-key gated. It still
operates on the node's validator key, so treat it as sensitive.

**Mitigation:**
- `server.apiKey` set + TLS (see §1/§2).
- Never expose this endpoint to the public internet; restrict to internal
  network only.

### 4. Minimal Rate Limiting — STILL OPEN

`ipcheck=false` by default. Even when enabled, `ipCheck()` only protects 4 of
55 endpoints (`getTip`, `getOutputs`, `getBalances`, `getAccountBalances`).
51 endpoints have no rate limiting at all.

**Mitigation:**
- Set `ipcheck=true`.
- Deploy a WAF or API gateway (Cloudflare, AWS WAF, nginx rate-limit) in
  front of the server.
- Tune `userDataService` thresholds for your traffic profile.

### 5. Prometheus Actuators Unauthenticated — FIXED (exposure), note retained

`management.endpoints.web.exposure.include` is now `health,info,prometheus`
on every server (was `*` on all but layer0-server). `loggers`/`threaddump`/
`heapdump`/`env` are no longer served on the API port. The remaining
`prometheus` endpoint is unauthenticated and publishes node metrics — keep it
behind the firewall/reverse proxy.

### 5b. CORS Open — FIXED (default off)

CORS previously allowed `*` origins with all methods on every JSON-RPC
endpoint. Now disabled by default; enable with an explicit allow-list:
`server.corsAllowedOrigins=https://app.bigtangle.org` (comma-separated).

### 6. Session Auth Cached Indefinitely — STILL OPEN

Once `checkAuth()` passes PQ verification, the result is cached in the HTTP
session without expiry. A stolen session cookie grants permanent access.

**Mitigation:**
- Invalidate sessions after a timeout.
- Rotate `sessionRandomNum` periodically.

## Consensus Layer

### 7. Double-Spend via Mempool — MITIGATED

Mempool admission verifies signatures and double-spends at ingress (README:
"mempool double-spend + signature verification at ingress"), and downstream
`ServiceBaseConfirmation` conflict detection / `resolveConflicts()` resolves
double-spends at chainlength depth. No action needed.

### 8. Batch Blocks Skip Re-Verification — STILL OPEN (review before mainnet)

`saveBatchBlock()` skips transaction re-verification and solidity checks. A
compromised peer can inject invalid blocks via batch sync.

**Mitigation:**
- Batch blocks come from trusted peers only. Ensure peer identity via
  permissioned mode.
- Verify the sync source — only sync from known, permissioned peers.

### 9. Beacon Header Validation Gap — STILL OPEN (review before mainnet)

`connectRewardBlock` for beacon blocks does not validate slot number,
proposer index, or RANDAO reveal (documented in blockchain.md). The PoS
hardening pass added RANDAO reveal application and proposer selection, but
full header validation per the beacon-chain spec is not yet enforced on
ingress.

**Mitigation:**
- Implement full beacon header validation before mainnet.

### 10. Single-Key Vault (Peg-Out) — PARTIALLY FIXED

M-of-N P2SH vault implemented (TODO Phase 4), but one node currently holds
all M private keys — a single node compromise still loses bridged funds.

**Mitigation:**
- Distribute the M keys across nodes (signing ceremony) before mainnet.
- Until then, keep the vault keys in a hardware security module (HSM).

## Crypto Layer

### 11. ~~FAKE_SIGNATURES Flag~~ — REMOVED

The `ECKey.FAKE_SIGNATURES` bypass no longer exists in the codebase (verified
by search). Nothing to do.

### 12. Post-Quantum Crypto Activation — UPDATED

ML-DSA-87 (FIPS 204) is the active signature suite (genesis keys are
ML-DSA-only); an optional height-gated SLH-DSA-SHA2-256s backstop exists for
the post-activation phase. The pq-dual-suite path is exercised by
`helper/testall.sh` with `DUAL_H=<height>`.

**Mitigation:**
- Keep monitoring NIST for algorithm deprecation — the height gate allows
  upgrading broken algorithms.

### 13. Broken DomainValidator.isValidTld() — STILL OPEN

`isValidTld()` still returns `true` unconditionally (the IANA list checks are
commented out). Domain-name token creation accepts any TLD, even nonexistent
ones.

**Mitigation:**
- Fix `DomainValidator.isValidTld()` to use the defined TLD lists instead
  of `return true`.

## Infrastructure

### 14. Default Database Credentials — PARTIALLY FIXED

`application.yml` ships with `username: root, password: test1234`, and
`common.env` uses the same for bootstrap. The server now logs a Mainnet
startup `SECURITY:` warning when the default password is in use, but nothing
hard-fails.

**Mitigation:**
- Override `DB_PASSWORD` in production; treat the startup warning as a
  launch blocker (cutover-runbook §6 greps for it).

### 15. Default Keystore Password — PARTIALLY FIXED

`KEYSTOREPW` defaults to `changeit`; the development `ca.pkcs12` keystore
was removed from the repo and gitignored. Use
`helper/prod/generate_keystore.sh` per deployment; the server warns on
Mainnet when the default password is in use.

### 16. Gossip Uses Plain HTTP — STILL OPEN

`GossipService` uses `"http://" + p + "/" + path` for inter-node gossip.
Peer-to-peer traffic is unencrypted.

**Mitigation:**
- Run all nodes with SSL enabled so gossip ports are HTTPS-served.
- Use a VPN/WireGuard mesh between nodes (the production topology already
  does: `SEED_HOSTS` on 10.8.0.x).

### 17. L0AnchorHandler Validation Gap — FIXED

`checkFull()`/`checkFormal()` now call `validateCrosstangle` (real block/tx
validation) instead of returning success unconditionally.

### 18. Container Runtime Hardening — FIXED

All server images (`helper/bigtangle/Dockerfile` + the per-module
Dockerfiles built by `helper/deploy.sh`) now: run as non-root UID 10001,
carry an actuator-based HEALTHCHECK (`HEALTHCHECK_PORT`/`SERVER_PORT`
aware), and accept `JAVA_OPTS`. CI scans pushed images with Trivy
(CRITICAL/HIGH fail the build).

### 19. Leaked Cloudflare Tunnel Credentials — REMEDIATION REQUIRED (operator action)

`helper/cloudflare/credentials.json` (tunnel secret) was committed to git
history and is removed from the current tree. Rotate the tunnel and purge the
file from history (`git filter-repo`/BFG + force push) — a fix no code change
can perform.
